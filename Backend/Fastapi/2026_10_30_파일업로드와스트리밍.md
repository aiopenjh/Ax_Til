## 2. 개념과 용어 정리

### 1) 전날 복습 — 미들웨어 순서와 TrustedHost

`@app.middleware`로 `middleware1`, `middleware2`를 차례로 등록한 뒤 `TrustedHostMiddleware`를 마지막에 등록했다. 나중에 등록한 것이 바깥 껍질이므로 요청은 TrustedHost → middleware2 → middleware1 → 경로 순서로 들어가고, 응답은 반대로 나온다. 허용 목록(`localhost`, `127.0.0.1`)에 없는 `Host`로 요청하면 `400 Invalid host header`로 가장 바깥에서 막힌다.

### 2) 파일 업로드 — multipart/form-data와 두 가지 받는 방법

브라우저나 Postman이 파일을 보낼 때는 보통 `multipart/form-data` 형식을 쓴다. 본문을 `boundary`라는 구분선으로 나눠 파일과 다른 폼 값을 함께 담는 형식이다. FastAPI에서 이 형식을 읽으려면 `python-multipart` 패키지가 필요하다.

| 구분              | `file: bytes = File()`                 | `file: UploadFile = File()`                                   |
| ----------------- | -------------------------------------- | ------------------------------------------------------------- |
| 받는 모양         | 파일 내용 전체가 `bytes` 하나로 들어옴 | 파일 객체. `read()`로 조금씩 읽을 수 있음                     |
| 메모리            | 파일 크기만큼 메모리를 씀              | 작으면 메모리, 일정 크기(약 1MB)를 넘으면 임시 파일(디스크)로 |
| 함께 오는 정보    | 내용만                                 | `filename`, `content_type`, `size`, `headers`                 |
| 어울리는 경우     | 아주 작은 파일                         | 사진·영상 등 일반적인 파일 업로드                             |

비유: `bytes`는 다 조립된 옷장을 현관으로 통째로 밀어 넣는 것, `UploadFile`은 상자로 나눠 받아 복도에 쌓아 두는 것.

헷갈리기 쉬운 점

- 경로 함수가 실행되는 시점에는 업로드 본문이 이미 서버에 다 들어와 있다(작으면 메모리, 크면 임시 파일). 함수 안에서 크기를 검사하면 '저장하지 않기'는 할 수 있어도 '받지 않기'는 못 한다. 업로드 크기 자체를 막으려면 앞단(웹 서버·프록시)의 본문 크기 제한도 함께 생각한다.
- `file.content_type`과 `file.filename`은 클라이언트가 보낸 값이다. 확장자나 MIME만 보고 안전한 파일이라고 믿지 않는다.
- Postman에서 파일을 보낼 때 `Content-Type: multipart/form-data`를 Headers에 직접 넣으면 `boundary`가 빠져 실패한다. Body → form-data에서 Key를 `file`(서버 인자 이름과 같게), 종류를 File로 두면 Postman이 알맞은 헤더를 만든다.

### 3) 조각 단위로 저장하기 — aiofiles와 while True

수업 코드는 업로드 파일을 1MB(`1024 * 1024`)씩 읽어 디스크에 쓴다. 한 번에 다 읽지 않으므로 파일이 커도 한 번에 쓰는 메모리는 조각 크기 정도로 유지된다.

```python
async with aiofiles.open(physical_target_path, "wb") as local_disk_file:  # wb: 바이너리 쓰기
    while True:
        binary_chunk = await file.read(1024 * 1024)  # 1MB씩 읽기
        if not binary_chunk:                          # 빈 값(b"")이면 다 읽은 것
            break
        await local_disk_file.write(binary_chunk)
await file.close()
```

| 요소                                       | 역할                                            | 기억할 점                                                                          |
| ------------------------------------------ | ----------------------------------------------- | ---------------------------------------------------------------------------------- |
| `aiofiles.open`                            | 파일 읽기·쓰기를 `await`로 기다릴 수 있게 함   | 일반 `open()`으로 큰 파일을 쓰면 그동안 다른 요청 처리가 막힐 수 있음             |
| `os.path.basename(file.filename)`          | 경로를 빼고 파일 이름만 남김                    | `../../secret.txt` 같은 이름으로 저장 위치를 벗어나는 것을 막는 기본 처리          |
| `seq_{id}_{파일명}`                        | 저장할 실제 파일 이름                           | 같은 이름 파일을 여러 번 올려도 덮어쓰지 않도록 번호를 붙임                        |
| `Path("storage")` + `mkdir(exist_ok=True)` | 저장 폴더 준비                                  | 상대 경로라 서버를 켠 위치 기준으로 생김. 실행 위치가 바뀌면 폴더 위치도 바뀜 |
| `except` 에서 `os.remove`                  | 저장 중 실패하면 반쯤 쓴 파일 삭제              | 실패 후 쓰레기 파일이 남지 않게 정리하고 `500`으로 응답                            |

### 4) 도메인 모델 — 파일 정보와 상태를 스스로 관리

`MultimediaAsset`은 저장한 파일의 번호·이름·크기·종류·상태·등록 시각을 담는 객체다. 만들 때 이름이 공백이거나 크기가 0 이하면 `ValueError`를 낸다. 상태는 `PENDING → PROCESSING → COMPLETED` 순서로만 바뀌게 메서드(`mark_as_processing`, `mark_as_completed`)에서 검사한다. 응답할 때는 `to_dict()`로 바꾸고, `AssetResponseSchema`(응답 모델)로 내보낼 필드를 정한다.

- 저장소는 `asset_repository: Dict[int, MultimediaAsset]`라는 메모리 딕셔너리다. 서버를 다시 켜면 목록은 사라지지만 `storage` 폴더의 파일은 남는다. 그래서 재시작 후에는 파일이 있어도 번호로 찾지 못한다.
- `asset_id_sequence`를 `global`로 늘리는 방식은 서버 프로세스가 하나일 때의 학습용이다.

### 5) StreamingResponse — 조각씩 내려보내는 다운로드

다운로드도 파일 전체를 읽어 한 번에 보내지 않고, 조각을 하나 만들 때마다 바로 보낸다. 조각을 하나씩 내놓는 함수가 비동기 제너레이터(`async def` + `yield`)다.

```python
async def get_file_chunk(file_path: Path, chunk_size: int = 1024 * 1024) -> AsyncGenerator[bytes, None]:
    async with aiofiles.open(file_path, "rb") as out_file:  # rb: 바이너리 읽기
        while True:
            chunk = await out_file.read(chunk_size)
            if not chunk:
                break
            yield chunk  # 한 조각씩 내보냄. 다음 조각은 요청받을 때 다시 읽음
```

`return StreamingResponse(get_file_chunk(경로), media_type=asset.content_type, headers=headers)`처럼 제너레이터를 넘기면, 조각이 나오는 대로 클라이언트로 흘려보낸다. 첫 조각이 바로 나가므로 큰 파일도 다운로드가 바로 시작된다.

| 응답 헤더             | 뜻                                          | 수업에서 고친 점                                                                                          |
| --------------------- | ------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| `Content-Disposition` | `attachment`면 화면에 띄우지 말고 저장하라는 뜻 | 한글 파일명은 그대로 넣으면 오류. `quote(파일명)`으로 바꾸고 `filename*=UTF-8''{바꾼이름}` 형식으로 보냄 |
| `Content-Length`      | 본문 전체 크기(바이트)                      | 헤더 값은 문자열이어야 함. `asset.file_size`(int)를 `str()`로 감싸야 함                                   |
| `Cache-Control`       | 캐시 사용 여부                              | `no-cache`: 저장해 둔 사본을 쓰기 전에 서버에 다시 확인                                                   |

헤더에는 기본적으로 영문·숫자 같은 글자(latin-1 범위)만 넣을 수 있다. 그래서 한글은 `%ED%95%9C...`처럼 퍼센트 인코딩한 뒤 'UTF-8로 인코딩한 이름'이라고 `filename*`로 표시한다.

### 6) BackgroundTasks — 오래 걸리는 일은 응답 뒤로

회원가입 후 안내 메일 보내기처럼 사용자가 결과를 기다릴 필요가 없는 일은 응답을 먼저 보내고 나중에 처리한다. 경로 함수 인자에 `background_tasks: BackgroundTasks`를 선언하고 `add_task(함수, 인자...)`로 예약하면, 응답을 보낸 뒤 그 함수가 실행된다.

```python
async def send_email(email: str):
    await asyncio.sleep(6)                     # 메일 발송에 6초 걸린다고 가정
    logger.info("회원가입 안내 메일 전송 완료...")

@app.get("/signup")
async def signup_done(background_tasks: BackgroundTasks):
    background_tasks.add_task(send_email, "test@test.org")  # 지금 실행하지 않고 예약만
    return {"message": "회원가입 완료 되었습니다."}          # 응답은 바로 나감
```

헷갈리기 쉬운 점

- 별도 서버나 작업 대기열이 아니라 같은 서버 프로세스 안에서 실행된다. 서버가 꺼지면 아직 안 끝난 작업은 사라진다. 꼭 해야 하는 일·아주 무거운 일은 Celery 같은 작업 큐를 따로 쓴다.
- `async def` 작업은 이벤트 루프에서 돌기 때문에, 안에서 `time.sleep()`처럼 막는 코드를 쓰면 그동안 다른 요청도 멈춘다. 기다릴 때는 `await asyncio.sleep()`처럼 `await` 가능한 함수를 쓴다. 일반 `def` 작업은 별도 스레드에서 실행된다.
- 작업이 실패해도 응답은 이미 나갔으므로 클라이언트는 모른다. 실패는 로그로 남기고, 필요하면 상태값(`PROCESSING` → `FAILED` 등)으로 기록한다.

### 7) 상태 코드 — 없음(404)과 사라짐(410)

| 코드  | 뜻                                       | 이번 실습에서                                                                                  |
| ----- | ---------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `201` | 새로 만들어짐                            | 업로드 성공 (`status_code=status.HTTP_201_CREATED`)                                            |
| `404` | 찾는 대상이 없음                         | 없는 번호 다운로드                                                                             |
| `410` | 있었지만 영구히 사라짐                   | 교재는 번호를 못 찾을 때도 410을 쓰는 곳이 있음. 처음부터 없던 번호라면 404가 더 일반적        |
| `413` | 본문이 너무 큼                           | 업로드 크기 제한을 넘었을 때 쓰는 코드                                                         |
| `500` | 서버 쪽 오류                             | 파일 저장 중 실패. 내부 오류 문구를 그대로 보여 주지 않도록 주의                               |

## 3. 예제 및 실습

### 예제 1 — 업로드 → 저장 → 다운로드 (수업 코드 chapter04-2 기준, 미실행)

수업 코드에서 흐름만 남긴 읽기용 코드다. 아래 코드를 따로 실행하지는 않았다. 헤더 관련 두 가지 오류는 수업 중 튜터님 코드에서 실제로 나서 고친 부분이다.

```python
import os
from pathlib import Path
from typing import AsyncGenerator
from urllib.parse import quote
import aiofiles
from fastapi import FastAPI, UploadFile, File, HTTPException, status
from fastapi.responses import StreamingResponse

app = FastAPI()
MEDIA_STORAGE_DIR = Path("storage")                    # 서버를 켠 위치 기준
MEDIA_STORAGE_DIR.mkdir(parents=True, exist_ok=True)
files: dict[int, dict] = {}                            # 학습용 메모리 저장소
seq = 1

@app.post("/assets", status_code=status.HTTP_201_CREATED)
async def upload_asset(file: UploadFile = File(description="업로드 파일")):
    global seq
    name = os.path.basename(file.filename)             # 경로 제거
    target = MEDIA_STORAGE_DIR / f"seq_{seq}_{name}"
    async with aiofiles.open(target, "wb") as out:
        while chunk := await file.read(1024 * 1024):   # 1MB씩, 빈 값이면 종료
            await out.write(chunk)
    await file.close()
    files[seq] = {"id": seq, "filename": name, "size": target.stat().st_size, "type": file.content_type}
    seq += 1
    return files[seq - 1]

async def get_file_chunk(path: Path) -> AsyncGenerator[bytes, None]:
    async with aiofiles.open(path, "rb") as f:
        while chunk := await f.read(1024 * 1024):
            yield chunk

@app.get("/assets/{asset_id}/download")
async def file_download(asset_id: int):
    asset = files.get(asset_id)
    if not asset:
        raise HTTPException(status_code=status.HTTP_404_NOT_FOUND, detail="파일을 찾을 수 없습니다.")
    headers = {
        "Content-Disposition": f"attachment; filename*=UTF-8''{quote(asset['filename'])}",  # 한글 파일명 대응
        "Content-Length": str(asset["size"]),                                               # 헤더 값은 문자열
    }
    path = MEDIA_STORAGE_DIR / f"seq_{asset_id}_{asset['filename']}"
    return StreamingResponse(get_file_chunk(path), media_type=asset["type"], headers=headers)
```

`while chunk := await file.read(...)`는 수업 코드의 `while True` + `if not chunk: break`를 한 줄로 줄인 것이다(바다코끼리 연산자 `:=`). 동작은 같다.

| 요청                                                          | 예상 결과                                                      | 확인하려는 차이                                    |
| ------------------------------------------------------------- | -------------------------------------------------------------- | -------------------------------------------------- |
| `POST /assets` (form-data `file` = `image.png`)               | `201`, `{"id":1,"filename":"image.png",...}`, `storage/seq_1_image.png` 생성 | 조각 단위 저장. 서버 로그에 파일 정보               |
| `POST /assets` (form-data `file` = `한글.png`)                | `201`, `storage/seq_2_한글.png` 생성                           | 파일 이름에 한글이 있어도 저장은 문제 없음          |
| `GET /assets/2/download`                                      | `200`, `content-disposition: attachment; filename*=UTF-8''%ED%95%9C%EA%B8%80.png` | 한글 파일명을 인코딩해서 보냄                       |
| `GET /assets/99/download`                                     | `404`                                                          | 없는 번호                                          |
| (고치기 전 코드) `Content-Length`에 int                       | `AttributeError: 'int' object has no attribute 'encode'`       | 헤더 값은 문자열이어야 함                           |
| (고치기 전 코드) `filename="한글.png"` 그대로                 | `UnicodeEncodeError: 'latin-1' codec can't encode ...`         | 헤더는 latin-1 범위 글자만 가능                    |

```bash
# -F: multipart/form-data로 파일 전송. Windows PowerShell에서는 curl.exe로 실행
curl -i -X POST http://127.0.0.1:8000/assets -F "file=@image.png"
# -o: 받은 내용을 지정한 이름으로 저장. -D -: 응답 헤더를 화면에 출력
curl -D - -o downloaded.png http://127.0.0.1:8000/assets/1/download
```

| ------------------------------------------------ | -------------------------------------------------------------------- | ------------------------------------------------------------ |

## 5. 오늘의 핵심

- ⭐️ 반드시 기억할 내용: 파일은 `UploadFile`로 받아 조각씩 저장하고, `StreamingResponse` + 비동기 제너레이터로 조각씩 내려보낸다. 기다릴 필요 없는 일은 `BackgroundTasks`로 응답 뒤에 처리한다.
- 💡 참고로 알아둘 내용: 다운로드 헤더의 `Content-Disposition: attachment`는 저장하라는 뜻이고, 한글 파일명은 `filename*=UTF-8''`로 보낸다. 단순 파일 응답은 `FileResponse`도 있다.
- ⚠️ 헷갈리기 쉬운 주의점: 헤더 값은 문자열·latin-1 범위여야 한다. 경로 함수가 실행될 때는 업로드가 이미 끝나 있다. `BackgroundTasks`는 같은 프로세스에서 돌며 실패해도 클라이언트는 모른다. 상대 경로 폴더는 서버를 켠 위치 기준이다.
- 한 문장 요약: 큰 데이터는 나눠서 받고·저장하고·보내고, 오래 걸리는 일은 응답과 떼어 놓아 서버가 멈추지 않게 한다.
