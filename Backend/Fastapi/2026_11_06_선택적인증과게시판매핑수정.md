## 2. 개념과 용어 정리

### 1) 선택적 인증 — 토큰이 없는 요청과 잘못된 토큰을 구분하기

비회원도 읽거나 쓸 수 있는 게시판이라면, 작성자를 확인하는 단계에서 무조건 로그인을 요구할 수 없다. 그렇다고 잘못된 토큰까지 비회원으로 바꿔 통과시키는 것은 다른 문제다.

| 요청 상태 | 선택적 사용자 조회 | 필수 사용자 조회 |
| --- | --- | --- |
| 자격 정보가 없음 | `None` 반환 | 인증 필요 예외 |
| 유효한 토큰·정상 회원 | `User` 반환 | `User` 반환 |
| Bearer 토큰이 만료·위조됨 | 토큰 검증에서 인증 예외 | 같은 인증 예외 |
| 로그아웃 토큰 | 블랙리스트 검증에서 인증 예외 | 같은 인증 예외 |
| 사용자 없음·탈퇴 | 사용자 상태 검사에서 예외 | 같은 검사 적용 |

```python
optional_bearer_security = HTTPBearer(auto_error=False)

async def resolve_optional_user(credentials, user_repo, session):
    if credentials is None:
        return None                     # 자격 정보가 없는 요청
    # 이후에는 토큰 검증·블랙리스트 검사·회원 조회를 진행한다.

async def resolve_current_user(current_user):
    if current_user is None:
        raise UnauthorizedException("인증 정보가 필요합니다.")
    return current_user
```

이 예시는 흐름만 줄인 것으로 실제 수업 함수에는 `Annotated`와 `Depends` 선언이 있다. `auto_error=False`가 모든 토큰 검증을 꺼 주는 설정은 아니다. Bearer 자격 정보 추출에서 자동 오류를 내지 않게 하고, 이후 분기를 직접 처리한다.

자격 정보가 '없음'으로 추출되는 구체적인 헤더 형식과 만료·위조된 Bearer 토큰은 구분해야 한다. 이 글의 표는 유효한 Bearer 형식으로 전달된 토큰의 검증 흐름을 기준으로 한다.

### 2) 필수·선택적 의존성을 따로 연결하기

| 의존성 | 실제 연결 함수 | 사용하는 곳 |
| --- | --- | --- |
| `get_optional_user` | `resolve_optional_user` | 비회원도 허용하는 게시판의 작성자·역할 확인 |
| `get_current_user` | `resolve_current_user` | 로그인이 필요한 기능 |
| `require_admin` | 관리자 역할 확인 함수 | 관리자 전용 기능 |

```python
app.dependency_overrides.update({
    get_optional_user: resolve_optional_user,
    get_current_user: resolve_current_user,
})

async def _get_current_author(user=Depends(get_optional_user)):
    if not user:
        return None
    return Author.member(user_id=user.id, username=user.name)
```

`_get_current_author` 안에 비회원 None 분기가 있어도 그 앞의 `get_current_user`가 필수 인증이면 요청이 먼저 막힌다. 선택적 사용자 조회에 의존하도록 바꿔야 비회원 분기에 도달할 수 있다.

### 3) 비회원 역할 None과 게시판의 ALL 권한

현재 요청자의 역할이 없는 것과 게시판이 모두에게 열려 있는 것은 서로 다른 값이다.

```python
def _check(self, user_role: Role | str | None, required: Role) -> bool:
    if user_role is None:
        return required == Role.ALL  # 비회원은 모두 공개된 기능만
    if isinstance(user_role, str):
        user_role = Role(user_role)
    return user_role.satisfies(required)
```

| 값 | 의미 | 확인할 점 |
| --- | --- | --- |
| `user_role is None` | 로그인하지 않은 요청자 | ALL을 요구하는 기능만 허용 |
| `Role.ALL` | 비회원 포함 허용하는 권한 수준 | '아무 검사도 안 한다'는 뜻이 아님 |
| `Role.USER` | 회원 권한 수준 | 일반회원 이상 역할 검사 |
| `Role.ADMIN` | 관리자 수준 | 상위 역할을 가중치로 비교 |

게시판에 접근할 수 있는가와 특정 글을 수정할 수 있는가는 별도 검사다. 공개 게시판이라도 남의 글을 마음대로 수정할 수 있는 것은 아니다.

### 4) PostMapper — 도메인이 요구하는 모양으로 복원하기

도메인의 게시글은 단순 `board_id` 인자가 아니라 `board_info` 값 객체를 사용한다. DB 모델을 도메인 객체로 만들 때 생성자 규격에 맞춰 묶어 줘야 한다.

| 변환 항목 | 잘못된 형태 | 올바른 형태 |
| --- | --- | --- |
| 게시판 정보 | `Post(board_id=...)`로 전달 | `BoardInfo(board_id=..., board_name=...)`로 조립 |
| 작성자 ID | `author_id`에 작성자 이름 전달 | `domain.author.author_id` 사용 |
| 비회원 비밀번호 | 존재하지 않는 `guest_password(...)` 함수처럼 호출 | 괄호로 조건식만 묶어 해시 문자열 또는 None 전달 |
| 권한 Enum | 존재하지 않는 `.edit_role_value` 접근 | `.edit_role.value`로 문자열 값 꺼내기 |

```python
# ORM → 도메인: 게시판 정보 값 객체
board_info = BoardInfo(
    board_id=model.board_id,
    board_name=model.board.board_name,
)

# 도메인 → ORM: 이름과 ID를 서로 바꾸지 않는다.
author_id = domain.author.author_id
guest_password = (
    domain.guest_password.hashed_value if domain.guest_password else None
)
```

ID·이름이 둘 다 문자열처럼 보여도 업무 의미가 다르고, 이 수업의 회원 ID는 UUID다. 필드 수가 같고 코드가 실행된다고 올바른 데이터 변환이라는 뜻은 아니다.

### 5) 관계 미리 로딩 — Mapper가 읽을 값도 조회 계획에 포함

위 Mapper는 `model.board.board_name`에 접근한다. 게시글만 조회하고 게시판 관계를 미리 읽지 않으면, 변환 과정에서 추가 DB 조회가 필요해질 수 있다. 비동기 환경의 암묵적 관계 로딩은 오류 원인이 될 수 있다.

```python
board: Mapped["BoardModel"] = relationship(
    "BoardModel",
    lazy="joined",  # 글을 읽을 때 게시판 관계를 함께 로딩
)
```

| 비교 | 관계를 미리 읽지 않음 | 수업의 `lazy="joined"` |
| --- | --- | --- |
| Mapper의 접근 | 그 시점에 추가 조회가 필요할 수 있음 | 게시판 정보를 함께 가져오도록 설정 |
| 모델 관계 | 게시글 → 게시판 단일 관계 | JOIN 기반 로딩 적용 |
| 주의점 | await 없는 I/O 문제 가능 | 이 관계가 불필요한 조회에도 함께 붙는 비용이 있음 |

수업 코드가 `joined`를 추가한 사실은 확인됐지만, 당시 실제 오류가 `MissingGreenlet`이었는지까지 보여 주는 실행 로그는 없다. 가능한 원인과 실제 관찰된 오류를 구분한다.

### 6) CommentMapper — model과 domain의 방향을 혼동하지 않기

댓글을 복원할 때는 입력으로 받은 ORM 객체의 컬럼을 읽어야 한다.

```python
return Comment(
    comment_id=model.comment_id,
    post_id=model.post_id,
    content=model.content,
    author=Author(author_name=model.author_name, author_id=model.author_id),
    created_at=model.created_at,    # to_domain의 입력은 model
    modified_at=model.modified_at,
    deleted_at=model.deleted_at,
    # 비회원 해시는 원문의 from_hash 분기에서 복원한다.
)
```

위 예시는 필드 방향을 보여 주는 발췌이며, 완전한 생성 인자 목록은 아니다. 이전 코드의 `model.author.author_name`, 정의되지 않은 `domain.author.author_id`, `domain.created_at` 등을 `model`의 실제 컬럼으로 고쳤다.

| 함수 | 입력 | 출력 | 읽을 기준 객체 |
| --- | --- | --- | --- |
| `to_domain(model)` | DB 모델 | 업무 객체 | `model` |
| `to_model(domain)` | 업무 객체 | DB 모델 | `domain` |
| `from_domain(domain)` | 업무 객체 | 응답 스키마 | 공개할 도메인 값 |

### 7) 댓글 수정·삭제 — 관리자, 본인, 비회원 비밀번호

`Comment.can_modify_or_delete`가 추가됐다. 판단 순서는 관리자 → 회원 작성자의 본인 여부 → 비회원 비밀번호 검증이다.

```python
if user_role == Role.ADMIN:
    return True
if not self.author.is_guest:
    return self.author.is_owner(requester_id)
if not raw_guest_password:
    return False
return self.verify_guest_password(raw_guest_password, hasher)
```

| 댓글 종류·요청자 | 코드에서 판단하는 조건 |
| --- | --- |
| 관리자 | 관리자 역할이면 허용 |
| 회원 댓글 | 작성자 ID와 요청자 ID가 같은가 |
| 비회원 댓글 | 입력 비밀번호가 있고 저장된 해시와 일치하는가 |
| 비회원 비밀번호 없음 | 거절 |

권한 메서드는 허용 여부를 반환하고, 응용 서비스는 그 결과에 따라 작업을 진행하거나 예외를 낸다. 댓글 권한 함수 하나가 추가됐다고 실제 HTTP 수정·삭제의 전 과정이 검증됐다는 뜻은 아니다.

비회원 작성자 팩토리 호출도 글·댓글 양쪽에서 `Author.guest(guest_name=req.guest_name)`으로 수정됐다. 생성 함수 인자 이름은 호출하는 쪽과 정확히 맞아야 한다.

### 8) 빈 검색어 — 생략과 빈 문자열의 경계

검색 스키마에서 `keyword`의 `min_length=1` 조건을 제거했다. `max_length=50`과 기본값 None은 유지한다.

| 입력 | 스키마·저장소 흐름 | 확인할 점 |
| --- | --- | --- |
| keyword 생략 | 기본값 None | 키워드 조건 없이 조회 |
| `keyword=` | 빈 문자열 허용 | 최소 길이 오류를 내지 않도록 변경 |
| 공백만 입력 | 저장소에서 `strip()` 결과 확인 | 비어 있으면 검색 조건을 만들지 않음 |
| 50자 초과 | 최대 길이 제한 | 입력 검증에서 거절 대상 |

빈 검색어를 허용하는 것과 모든 입력 검증을 없애는 것은 다르다. 요청 스키마와 저장소가 같은 의미로 '검색 조건 없음'을 처리하는지 함께 본다.

### ⭐️ 필수 (실무 핵심 90%) - 반드시 기억

| 용어/명령어 | 뜻 | 기억할 점 / 주의점 |

### 수업 예제 — 인증·변환 경계별로 따라가기 (미실행)

```text
토큰 없음 → 선택적 사용자 None → 작성자·역할 None
         → 게시판 ALL 권한 확인 → 비회원 이름·비밀번호 확인

토큰 있음 → 서명·만료·차단 확인 → 사용자 조회 → 작성자·역할 변환

글 조회 → PostModel + BoardModel → BoardInfo·Author 조립
        → Post → 응답 스키마
```

| 확인할 요청·변환 | 코드에서 기대하는 동작 | 직접 확인할 근거 |
| --- | --- | --- |
| 토큰 없이 공개 게시판 조회 | 선택적 인증 경로 사용 | 실제 응답·의존성 호출 흐름 |
| 만료 토큰으로 조회 | 인증 예외 | HTTP 상태·오류 본문 |
| 비회원 글·댓글 작성 | 올바른 팩토리 인자 사용 | 저장된 작성자·해시와 응답 |
| 게시글 복원 | BoardInfo와 작성자 ID 일치 | DB 값·도메인 값 비교 |
| 댓글 수정·삭제 | 관리자·본인·비밀번호 규칙 적용 | 허용·거절 요청 각각 확인 |
| 빈 검색어 조회 | 검색 조건 없이 목록 조회 | 생략·빈 문자열·공백 결과 비교 |

## 5. 오늘의 핵심

- ⭐️ 반드시 기억할 내용: 비회원 허용은 인증 의존성부터 연결해야 하고, 토큰 없음과 잘못된 토큰을 구분한다.
- 💡 참고로 알아둘 내용: Mapper는 단순 복사가 아니라 값 객체를 조립하는 경계다. 관계 미리 로딩도 그 변환에 필요한 데이터를 기준으로 정한다.
- ⚠️ 헷갈리기 쉬운 주의점: 이름과 ID, model과 domain, 값과 함수 호출을 혼동하지 않는다. 권한 검사부터 응답까지 실제 요청 흐름을 확인한다.
- 한 문장 요약: 계층이 연결되는 경계에서 인증 조건과 데이터 모양이 맞는지 하나씩 대조한다.
