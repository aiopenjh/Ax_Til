## 2. 개념과 용어 정리

### ⭐️ 필수 (실무 핵심 90%) - 반드시 기억

| 용어/명령어 | 뜻 | 기억할 점 / 주의점 |
| --- | --- | --- |
| 2단계 검색 | 먼저 후보를 찾고, 그 후보만 다시 평가하는 구조 | 1차 검색에서 빠진 문서는 리랭커가 새로 찾아오지 못한다. |
| Re-ranking | 질문과 후보 문서의 관련성을 다시 평가해 순서를 정하는 과정 | 항상 1위가 바뀌거나 검색 품질이 좋아지는 것은 아니다. |
| Cross-Encoder | 질문과 문서를 한 쌍으로 입력받아 관련성을 채점하는 모델 | 후보마다 모델 계산이 필요하므로 후보 수와 처리 시간을 함께 본다. |
| `k` / `top_n` | `k`는 1차 후보 수, `top_n`은 재정렬 후 남길 수 | 튜터 예제는 3건을 가져와 2건을 남긴다. 같은 설정값이 아니다. |
| `ContextualCompressionRetriever` | 기본 검색기와 후처리기를 연결하는 랭체인 검색기 | 이 예제의 후처리는 문서 선택·재정렬이다. 문장을 요약하는 코드는 아니다. |

### 💡 참고 (검색용) - 이해만 하고 넘어가기

| 패턴/문법 | 뜻 | 필요할 때 찾는 팁 |
| --- | --- | --- |
| Bi-Encoder | 질문과 문서를 따로 벡터로 만든 뒤 비교하는 방식 | 문서 벡터를 미리 저장해 검색에 활용할 수 있다. |
| RRF와 리랭킹 | RRF는 여러 결과의 순위를 합치고, Cross-Encoder는 질문·문서 쌍을 다시 채점 | 이번 공개 코드는 BM25 뒤에 리랭커를 붙인다. 하이브리드 검색을 실행한 결과로 섞지 않는다. |
| `CrossEncoderReranker` | Cross-Encoder 점수로 후보를 정렬하고 상위 문서를 반환하는 구성요소 | `model`과 `top_n`을 확인한다. 모델 점수를 정답 확률로 단정하지 않는다. |

## 3. 예제 및 실습

### 실습 내용

#### 1) 튜터 코드의 연결 구조

[05_04.ipynb](https://github.com/yonggyo1125/ax_study/blob/ecbc2d3b96c64b5d4c29176c96e438860b409a2c/12_rag/chapter05/05_04.ipynb)는 다음 순서로 구성된다.

```text
질문
  → BM25: 후보 3건
  → Cross-Encoder: 질문과 각 후보를 다시 채점
  → 상위 2건 선택
```

- 문서는 사내 IT 규정 네 건이며, BM25 토크나이저는 `text.split()`을 사용한다.
- 최종 비교 셀에 연결된 검색기는 `bm25_retriever`, 후보 설정은 `k=3`이다.
- 리랭커 모델은 `Dongjin-kr/ko-reranker`, 최종 선택 설정은 `top_n=2`다.
- `ContextualCompressionRetriever`에 기본 검색기와 리랭커를 연결한 뒤 같은 질문으로 전후 결과를 출력한다.
- 노트북 앞뒤에 비슷한 설정 셀이 반복된다. 마지막 비교에서 어떤 변수에 연결된 검색기를 사용하는지 먼저 따라간다.

#### 2) 저장 출력으로 확인한 변화

질문은 로그인 과정에서 비밀번호를 여러 번 틀렸을 때 어떻게 처리하는지 묻는 내용이다.

| 구분 | 저장된 결과 순서 | 결과 수 |
| --- | --- | ---: |
| BM25 | 계정 관리 → 장비 지급 규정 → 원격 근무 가이드 | 3 |
| 리랭킹 후 | 계정 관리 → 원격 근무 가이드 | 2 |

이 출력에서 계정 관리는 처음부터 1위다. 리랭킹으로 바뀐 것은 장비 지급 문서가 최종 두 건에서 빠지고, 원격 근무 문서가 두 번째로 남은 점이다. 따라서 “리랭커가 틀린 1위를 바로잡았다”라고 이 실행을 설명하면 맞지 않는다.

교안의 설명용 전후 순서와 공개 노트북에 저장된 순서가 다르므로 결과를 섞지 않는다. 질문 하나의 문서 순서만으로 전체 정확도나 답변 품질이 개선됐다고 결론 내릴 수도 없다.

[05_04_2.ipynb](https://github.com/yonggyo1125/ax_study/blob/ecbc2d3b96c64b5d4c29176c96e438860b409a2c/12_rag/chapter05/05_04_2.ipynb)는 기본 검색기·모델·리랭커를 연결하는 코드까지 있다. 검색 비교 셀과 검색 결과 출력은 없어 별도의 성공 사례로 세지 않는다.

#### 3) 복습 연습: 후보 안에서만 다시 고르기

첫 파일은 `rerank_candidates.py`, 구현할 함수는 `select_top`이다. 다음 코드는 모델 추론 대신 고정한 가상 점수를 사용한다. 실제 Cross-Encoder의 성능을 재현하는 코드는 아니다.

할 일:
1. `candidates`에 있는 ID만 점수 내림차순으로 정렬한다.
2. 앞에서 `top_n`개만 반환한다.
3. 후보에 없는 D의 점수가 높아도 결과에 들어오지 않는지 확인한다.

시작 코드:

```python
def select_top(candidates, scores, top_n):
    # TODO: 후보 목록 안에서만 정렬하고 상위 top_n개 반환
    raise NotImplementedError

scores = {"A": 0.9, "B": 0.2, "C": 0.7, "D": 0.99}
print(select_top(["A", "B", "C"], scores, 2))
print(select_top(["B", "C"], scores, 2))
```

구현 후 예상 출력:

```text
['A', 'C']
['C', 'B']
```

<details>
<summary>확인용 답안</summary>

```python
def select_top(candidates, scores, top_n):
    return sorted(candidates, key=lambda doc: (-scores[doc], doc))[:top_n]
```

</details>

실행 명령은 `python rerank_candidates.py`다. 외부 라이브러리·API 키·DB는 필요 없다. 시작 코드 그대로 실행하면 미구현 상태를 알리는 `NotImplementedError`가 나므로 함수를 먼저 채운다.

### 실행 결과

- 자료에서 확인한 부분: 튜터 저장 출력의 3건 → 2건 변화와 1위 유지.
- 연습의 기대 결과: 후보에 없는 D는 선택되지 않고, A를 후보에서 빼면 A 역시 복구되지 않는다.
- 확인하지 않은 부분: 개인 노트북 실행, 실제 모델 처리 시간, 여러 질문에 대한 품질 평가, 최종 답변 생성.

## 4. 실수 및 트러블슈팅

### 발생한 문제 요약

#### 1) 교안 예시와 저장 출력의 순서가 다름

- 상황: 교안의 설명용 BM25 순서와 `05_04.ipynb` 마지막 셀의 저장 순서가 다르다.
- 원인: 차이가 있다는 사실은 확인했지만, 어느 실행 조건 때문에 달라졌는지는 저장 자료만으로 확정할 수 없다.
- 해결: 질문·문서·토크나이저·후보 수·실행 순서·패키지 환경을 맞춘 뒤 같은 실행에서 전후 결과를 함께 기록한다.
- 해결 결과: 이번 글에서는 공개 노트북에 저장된 결과만 해당 실행의 결과로 사용했다. 재실행으로 원인을 해결한 것은 아니다.

#### 2) “압축”을 문장 요약으로 읽기 쉬움

- 상황: 검색기 이름에 `Compression`이 들어가지만 예제는 최종 문서 두 건을 남긴다.
- 원인: 후처리 역할을 이름만 보고 요약 생성으로 해석하면 실제 코드와 어긋난다.
- 해결: `base_compressor`에 연결된 `CrossEncoderReranker`와 `top_n=2`를 확인한다.
- 해결 결과: 확인된 동작은 후보 재정렬·선택이다. 문장 요약이나 답변 생성 완료로 기록하지 않는다.
