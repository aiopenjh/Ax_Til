## 2. 개념과 용어 정리

### 1) 키워드 검색과 벡터 검색

키워드 검색은 입력한 단어나 표현과 문서의 표현이 맞는지를 바탕으로 자료를 찾는다. 벡터 검색은 질문과 문서를 숫자 배열로 표현하고 의미적으로 가까운 자료를 찾는다.

| 필요한 검색 | 검토할 방식 | 이유 |
| --- | --- | --- |
| 모델명·오류 코드처럼 정확한 표현 찾기 | 키워드 검색 | 특정 식별자를 정확히 구별해야 함 |
| 표현이 달라도 비슷한 뜻 찾기 | 벡터 검색 | 같은 의미를 다른 말로 질문할 수 있음 |
| 정확한 표현과 비슷한 의미를 함께 활용 | Hybrid Search | 두 검색 방식의 장점을 함께 사용 |

복합기 앱에 적용한다는 가정으로 생각해봤다. 정확한 오류 코드로 매뉴얼을 찾는 경우와 ‘인쇄하면 검은 줄이 생긴다’는 증상으로 찾는 경우는 검색 요구가 다르다. 이 사례는 개념 이해를 위한 대화 예시이며 실제로 구현한 기능은 아니다.

### 2) TF와 IDF

- TF(Term Frequency): 한 문서 안에서 특정 단어가 얼마나 자주 등장하는지와 관련된 값.
- IDF(Inverse Document Frequency): 여러 문서에 흔하게 등장하는 단어의 구별력을 낮추고, 상대적으로 드문 단어의 구별력을 반영하는 값.

한 문서에서 자주 나오는 단어는 그 문서의 주제를 나타낼 수 있다. 하지만 모든 문서에서 흔하게 나오는 단어라면 특정 문서를 구별하는 힘은 약하다. 두 관점을 함께 사용해 단어의 중요도를 계산한다.

### 3) BM25와 단어 빈도 포화

판서에서는 단어 빈도 증가에 따라 점수가 계속 커지는 직선과, 처음에는 올라가다가 증가 폭이 줄어드는 BM25 곡선을 비교했다.

같은 검색어가 문서에서 반복되면 관련성 점수에 기여하지만, 반복 횟수가 늘어날수록 추가 반복의 효과는 줄어든다. 단어를 많이 반복한 문서가 점수를 과하게 받는 것을 줄이는 원리다.

BM25와 TF-IDF를 같은 알고리즘으로 보지는 않는다. 또 TF를 변환하는 방법에 따라 점수 계산이 달라지므로 모든 TF-IDF 구현이 항상 직선으로 증가한다고 일반화하지 않는다.

### 4) Hybrid Search와 가중치

키워드 검색과 벡터 검색을 함께 사용하고 결과를 결합하는 방식이다. 어떤 질문에는 정확한 용어가 중요하고, 어떤 질문에는 의미적 유사성이 중요할 수 있다.

필요에 따라 두 검색의 비중을 조절할 수 있지만, BM25 점수와 벡터 검색 점수는 범위와 의미가 다르므로 원점수를 단순히 더하는 방식은 주의해야 한다.

판서의 점수 범위 비교는 서로 다른 점수 체계를 설명하는 예시로 이해한다. 일반적인 코사인 유사도의 수학적 범위는 -1~1이며, 검색 서비스가 변환해 반환하는 점수와 구분한다.

### 5) RRF는 검색 순위를 합치는 방식

RRF(Reciprocal Rank Fusion)는 여러 검색 결과에서 문서가 몇 등으로 나왔는지를 바탕으로 순위를 결합한다. BM25와 RRF는 대체 관계가 아니라 역할이 다르다.

```text
BM25: 키워드 검색에서 문서별 점수와 순위를 계산
벡터 검색: 의미적 유사성을 바탕으로 순위를 계산
RRF: 각 검색의 순위를 이용해 결과를 결합
```

문서 하나에 대한 기본 RRF 점수는 각 검색에서 다음 값을 계산해 더하는 형태다.

```text
각 검색의 기여 점수 = 1 / (k + 순위)
최종 점수 = 해당 문서가 등장한 각 검색의 기여 점수 합계
```

여기서 k는 순위 차이가 점수에 미치는 영향을 조절하는 상수다. 이전 실습의 `retriever`에 사용한 `k=2`, 즉 가져올 문서 개수와는 다른 설정이다.

### 6) Query 변환

사용자 질문을 검색에 유리한 형태로 바꾸는 과정이다. 판서에서는 다음 흐름을 확인했다.

```text
사용자 질문 → LLM → 검색에 유리한 질문으로 변환
```

원래 의도를 유지하면서 검색에 필요한 대상이나 핵심 표현을 명확하게 하는 것이 중요하다. 질문을 바꾼 결과가 실제 검색 품질을 개선하는지는 확인해야 한다.

### 7) HyDE는 가상 문서를 검색 단서로 사용

HyDE(Hypothetical Document Embeddings)는 질문에 대해 가상의 답변 문서를 생성하고, 그 문서를 임베딩해 관련된 실제 문서를 검색하는 방식이다.

```text
질문 → LLM이 가상 문서 생성 → 가상 문서 임베딩
     → 실제 문서 집합에서 검색 → 실제 검색 자료를 답변 근거로 활용
```

가상 문서에는 틀린 세부 내용이 포함될 수 있다. 가상 문서 자체를 사실의 근거로 믿는 것이 아니라 실제 자료를 찾기 위한 단서로 사용한다.

### 8) 이후 목차에서 짚은 내용

판서에서는 Re-ranking, 맥락 압축·검색 최적화, 평가셋 구성과 검색·생성 지표, 실패 원인 분석으로 이어지는 목차도 확인했다.

맥락 압축은 검색된 자료에서 질문에 필요한 정보를 추려 전달하는 것과 연결된다. 필요한 근거를 잃지 않도록 해야 한다. 평가셋과 결과 비교는 검색 방식을 바꿨을 때 실제로 개선됐는지 판단하는 데 중요하다.

이 항목들은 목차를 짚은 범위이며, 각 기능을 상세 실습까지 완료했다는 뜻은 아니다.

### 9) 쉬는 시간 이후 검색 평가 지표

10:18부터 수업 화면 확인을 재개했다. RAG 평가에서는 필요한 문서를 찾는 검색 단계와, 근거를 바탕으로 답하는 생성 단계를 나눠 본다. 10:20~10:25 판서에 정밀도와 재현율, 두 지표를 검색 문맥·청크에 연결하는 설명이 등장했다. 정밀도 식 `TP / (TP + FP)`와 재현율 식의 의미를 확인했다.

| 지표 | 검색에서 묻는 질문 | 기본 계산 |
| --- | --- | --- |
| 정밀도(Precision) | 가져온 문서 중 필요한 문서는 얼마나 되나? | 필요한 문서를 가져온 수 / 가져온 문서 수 |
| 재현율(Recall) | 찾아야 할 문서 중 얼마나 찾아냈나? | 필요한 문서를 가져온 수 / 전체 필요한 문서 수 |

개념 보충으로 관련 문서를 정답이라고 보는 기본 이진 관련성 평가에 연결하면 다음과 같다.

- TP: 필요한 문서를 가져옴.
- FP: 필요하지 않은 문서를 가져옴.
- FN: 필요한 문서를 가져오지 못함.
- 정밀도 = `TP / (TP + FP)`.
- 재현율 = `TP / (TP + FN)`.

정밀도는 결과에 불필요한 자료가 얼마나 섞였는지, 재현율은 필요한 근거를 얼마나 놓쳤는지 살펴보는 관점이다. 두 지표는 같은 비율이 아니며, 평가하려면 어떤 문서가 필요한지에 대한 기준이 있어야 한다.

판서에서 재현율의 누락 항목은 `NF`처럼 적혔지만 ‘오답으로 예측했으나 실제 정답’이라는 설명을 기준으로 표준 표기 `FN`으로 정리한다.

판서는 질문 키워드와 문맥(context)에 포함된 내용을 연결해 설명했다. 실제 검색 평가에서 관련성은 단어 포함 여부만으로 확정하지 않는다. 질문에 답할 근거가 있는지에 대한 판단과 단순 키워드 일치를 구분해야 한다. 의미가 같은 다른 표현으로도 관련 문서가 검색될 수 있다.

10:27~10:29에는 정밀도를 ‘문맥이 정답에 기여하는 정도’와 연결하고, 재현율이 낮을 때의 대응을 설명했다. 판서에서는 재검색과 청크 크기 증가를 개선 후보로 제시했다.

재현율이 낮으면 필요한 근거를 검색에서 놓쳤는지 먼저 확인한다. 청크 크기를 키우면 잘려 있던 근거가 함께 포함될 수 있지만, 관련 없는 내용도 늘어날 수 있다. 청크 크기 증가가 항상 정답은 아니며 실제 질문에서 정밀도·재현율이 어떻게 변하는지 비교해야 한다.

### 10) 정밀도와 재현율을 함께 보는 F1-score

10:31 판서에서 정밀도 0.1, 재현율 0.9 예시를 확인했다. 관련 자료의 상당수는 찾았지만 가져온 결과에는 불필요한 자료가 많이 섞인 경우로 해석할 수 있다. 이 수치를 최종 답변의 정답률로 해석하지 않는다.

10:32~10:33에는 정밀도와 재현율의 조화평균인 F1-score와 다음 식을 확인했다.

```text
F1 = 2 × Precision × Recall / (Precision + Recall)
```

한쪽 지표가 낮으면 다른 쪽만 높아도 F1이 높게 나오기 어렵다. 보충 계산으로 정밀도 0.1, 재현율 0.9이면 산술평균은 0.5이지만 F1은 0.18이다. 정밀도와 재현율을 그냥 더해 2로 나누는 것과 구분한다.

### 11) 생성 평가: 충실도와 답변 관련성

10:35~10:37 판서에서 생성 평가 지표로 충실도(Faithfulness)와 답변 관련성이 등장했다. 충실도는 검색된 문서(context)의 사실을 기반으로 답했는지를 확인하는 방향으로 설명했다.

검색 평가가 필요한 근거를 잘 찾아왔는지를 본다면, 충실도는 생성된 답변이 그 근거에서 벗어나지 않았는지를 본다. 참고 문서에 없는 내용을 모델이 덧붙이는 문제를 구분하는 데 사용한다. 문서 자체가 사실인지 확인하는 작업과도 구분한다.

10:39에는 답변 관련성(Answer Relevance)을 질문의 목적·의도에 부합하는지와 연결했다. 판서에는 질문과 답변에서 임베딩 유사도로 이어지는 흐름이 나타났다. 구체적인 평가 도구의 계산 절차까지 확인한 것은 아니므로, 이 판서만으로 모든 답변 관련성 지표를 단순한 질문·답변 간 코사인 유사도라고 단정하지 않는다.

충실도와 답변 관련성은 별개다. 참고 문서에 근거한 내용이어도 질문에서 요구한 내용에 답하지 않으면 관련성이 낮을 수 있다.

### 12) 평가셋과 Golden Set

10:41~10:42에는 7장 평가·개선 구현 목차로 돌아가 평가셋 구축을 연결했다. 판서에 질문, 모범 답변, 근거 문서, 답변 항목과 ‘Golden Set’ 표기가 등장했다.

비교 기준으로 삼을 질문·모범 답변·근거를 마련하고, 시스템이 실제로 만든 답변과 검색 결과를 그 기준으로 평가하는 흐름으로 이해한다. 모범 답변과 시스템의 출력은 역할이 다르므로 구분해서 기록한다. 평가 도구 실행이나 데이터셋 파일 작성까지 확인한 것은 아니다.

| RRF의 k | 순위별 점수 차이를 조절하는 상수 | 검색 결과 개수 k와 혼동하지 않기 |
| Query 변환 | 질문을 검색하기 좋은 형태로 변환 | 의도 보존과 검색 개선을 함께 확인 |
| HyDE | 가상 문서로 실제 문서를 검색 | 생성 문서를 사실의 근거로 사용하지 않기 |

## 3. 예제 및 실습

### 실습 내용

#### 1) 판서에서 확인한 RRF 계산

판서에서는 k=60을 사용했다.

```text
1등의 기여 점수 = 1 / (1 + 60) = 1/61
2등의 기여 점수 = 1 / (2 + 60) = 1/62
```

보충 예시로, 어떤 문서가 키워드 검색 1등이고 벡터 검색 2등이라면 두 기여 점수를 더해 최종 순위 계산에 사용한다. 검색 엔진마다 서로 다른 원점수를 직접 비교할 필요를 줄일 수 있다.

#### 2) 정밀도·재현율 계산 예시

다음은 이해를 돕기 위해 대화에서 든 예시이며 실제 검색 실험 결과는 아니다.

```text
찾아야 할 관련 문서: 총 5개
검색으로 가져온 문서: 총 10개
그중 실제로 관련 있는 문서: 3개

TP = 3, FP = 7, FN = 2
정밀도 = 3 / 10 = 30%
재현율 = 3 / 5 = 60%
F1 = 2 × 0.3 × 0.6 / (0.3 + 0.6) = 40%
```

#### 3) 문서가 없는 상태에서 기본 세팅을 맡기는 경우

대화에서 다음 상황을 질문했다.

> 수업 내용을 모르는 상태에서 ‘키워드 검색 기능을 만들고 싶다. 문서는 나중에 줄 테니 기본 세팅만 해봐’라고 하면 어떤 방식을 고를까?

논의한 기본 접근은 다음과 같다.

1. 문서를 넣을 자리와 검색어 입력·결과 표시 흐름을 준비한다.
2. 처음에는 단어가 포함된 부분을 찾는 단순 검색으로 연결한다.
3. 문서가 없을 때는 결과를 비워두고 검색이 완료된 것처럼 꾸미지 않는다.
4. 실제 문서를 받으면 형식·분량과 검색 예시를 확인한다.
5. 결과가 너무 많으면 관련도 순위, 표현이 달라도 찾아야 하면 의미 검색을 검토한다.

이것은 앞으로 구현을 요청할 때의 접근 방법이며, 이번에 실제 프로젝트를 새로 구성한 작업은 아니다.

### 실행 결과

- 정상적으로 된 부분: 판서와 대화 예시를 바탕으로 RRF 기여 점수, 정밀도·재현율·F1을 계산했다.
- 새롭게 확인한 부분: 검색 방식마다 원점수 범위가 달라도 순위를 기준으로 결과를 합칠 수 있다. 예제는 계산을 위한 자료이며 검색 코드 실행이나 성능 측정은 하지 않았다.

## 4. 실수 및 트러블슈팅

### 발생한 문제 요약

#### 1) BM25와 RRF의 역할 혼동

- **상황**: 키워드 검색을 구현할 때 BM25와 RRF 중 하나를 선택하는 것으로 생각하기 쉽다.
- **원인**: 문서별 점수를 계산하는 단계와 여러 검색 결과를 합치는 단계가 섞였다.
- **해결**: BM25로 키워드 검색 순위를 구하고, 여러 검색기가 필요할 때 각 순위를 RRF에 넣는다.
- **해결 결과**: BM25와 RRF를 함께 사용할 수 있는 조건을 구분했다.

#### 2) 검색 기능에 필요한 수준 정하기

- **상황**: 문서가 나중에 들어오는 키워드 검색 기능에 어떤 검색 기법이 필요한지 고민했다.
- **원인**: 자료 형식과 분량, 사용자가 실제로 입력할 검색어가 아직 정해지지 않았다.
- **해결**: 단순 검색부터 만들고 실제 질문으로 결과를 비교하면서 순위, 의미 검색, 재정렬의 필요성을 판단한다.
- **해결 결과**: 실제 자료를 받은 뒤 어떤 기준으로 구현을 개선할지 정리했다.

## 5. 오늘의 핵심

- ⭐️ 반드시 기억할 내용: 키워드 검색·벡터 검색·순위 결합은 역할이 다르다.
- ⭐️ 반드시 기억할 내용: RRF는 서로 다른 검색의 순위를 바탕으로 결과를 합친다.
- ⭐️ 반드시 기억할 내용: 정밀도는 가져온 결과의 관련성, 재현율은 필요한 근거를 찾아낸 범위를 본다.
- ⭐️ 반드시 기억할 내용: 검색 결과의 품질과 생성 답변의 품질은 구분한다. 답변이 참고 문서에 근거하는지, 질문의 의도에 답하는지를 각각 확인한다.
- 💡 참고로 알아둘 내용: 질문 재작성과 HyDE는 검색 입력을 개선하는 방법이다.
- ⚠️ 헷갈리기 쉬운 주의점: RRF의 k와 검색 결과 개수 k를 구분한다. HyDE의 가상 문서는 실제 근거가 아니다.
- 한 문장 요약: 기술 이름을 전부 외우기보다 어떤 자료를 어떻게 찾고 싶은지 정하고, 실제 검색 결과가 요구를 만족하는지 확인한다.

## 6. 느낀 점과 다음 학습

- 잘 이해한 부분: 키워드 검색, 벡터 검색, 순위 결합은 서로 다른 단계에 쓰인다.
- 아직 어려운 부분: 실제 문서에서 검색 요구에 맞는 기법과 설정을 판단하는 일.
- 다음에 복습할 내용: 같은 질문과 문서로 검색 결과를 비교하고 정밀도·재현율이 어떻게 달라지는지 확인하기.
- 오늘의 느낀 점: 검색 기능을 AI에게 맡기더라도 어떤 자료에서 무엇을 찾을지, 어떤 결과가 나오면 쓸 만한지는 내가 정해야 한다. 작은 예제에서 결과를 비교해보는 편이 기술 이름을 외우는 것보다 도움이 된다.
