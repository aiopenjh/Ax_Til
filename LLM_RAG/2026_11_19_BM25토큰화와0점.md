## 2. 개념과 용어 정리

### ⭐️ 필수 (실무 핵심 90%) - 반드시 기억

| 용어/명령어 | 뜻 | 기억할 점 / 주의점 |
| --- | --- | --- |
| Self-Attention | 한 토큰이 같은 입력 안의 다른 토큰을 얼마나 참고할지 계산하는 방식 | 어텐션은 트랜스포머 블록 안의 한 부분이다. |
| FFN | 어텐션을 거친 각 토큰의 벡터를 다시 변환하는 층 | 토큰끼리 정보를 섞는 어텐션과 역할이 다르다. |
| BM25 | 질문에 들어 있는 토큰으로 문서의 관련도를 계산하는 키워드 검색 방식 | 정확히 일치한 토큰을 기준으로 계산한다. 문서 자체의 정답 여부를 채점하지 않는다. |
| TF / IDF | 문서 안에서의 등장 횟수 / 전체 문서에서 얼마나 드문지에 따른 가중치 | 같은 단어를 반복할수록 점수의 추가분은 줄어든다. 길이 보정도 들어간다. |
| `text.split()` | 공백을 기준으로 문자열을 자른다. | 조사나 문장부호를 떼지 않는다. `VPN`과 `VPN을`은 서로 다른 토큰이다. |
| `k` | 검색기가 돌려주는 최대 후보 수 | `k=3`이면 동점 0점인 후보도 나올 수 있다. 점수 기준으로 걸러내는 설정과는 다르다. |

## 3. 예제 및 실습

### 실습 내용

#### 1) 트랜스포머는 어텐션 한 번으로 끝나지 않는다

토큰을 임베딩하고 위치 정보를 넣은 뒤, 어텐션과 FFN이 있는 블록을 여러 번 통과한다. 원래 트랜스포머는 인코더와 디코더를 모두 쓴다. 인코더는 입력의 표현을 만들고, 디코더는 이전에 생성한 토큰과 인코더의 출력을 이용해 다음 토큰을 예측한다. GPT처럼 디코더만 쓰는 모델에서는 인코더의 출력을 참조하는 크로스 어텐션이 없다.

#### 2) BM25에서 0점이 나오는 두 가지 이유

사내 망에 들어가려다 비밀번호를 여러 번 틀렸을 때의 처리 방법을 묻는 검색 예제다. 질문과 문서가 모두 공백으로만 나뉘므로, 질문의 `비밀번호`와 문서의 `비밀번호를`은 서로 만나지 않는다. 실제로 겹친 `사내`는 문서 네 개 가운데 두 개에 있다. 이 예제의 BM25Okapi에서 희귀도는 `log((4 - 2 + 0.5) / (2 + 0.5)) = 0`이므로, 두 번 등장한 문서라도 `사내`로 얻는 점수는 0이다. 다른 BM25 구현에서도 문서 절반에 나오는 단어가 항상 0인 것은 아니다.

| 질문에서 바꾼 것 | 예제 결과 | 읽는 방법 |
| --- | --- | --- |
| 원래 질문 | 문서 네 건 전부 0점 | 뜻이 비슷해도 맞는 토큰이 없거나, 맞는 토큰의 가중치가 0이다. |
| `VPN` 추가 | 여전히 전부 0점 | 실제 토큰은 `VPN을`이다. |
| `VPN을` 추가 | 원격 근무 가이드 약 0.83점 | VPN 접속 근거는 찾지만 비밀번호 실패로 계정이 잠기는 질문의 답은 아니다. |
| `로그인` 추가 | 계정 관리 문서 약 0.76점 | 이 문서에 5회 연속 실패 시 계정이 잠긴다는 근거가 있다. |

#### 3) 복습 예제: 공백만으로 나누면 무엇이 겹치는가

용어를 줄인 작은 예제다. 아래 코드는 BM25 점수 전체가 아니라 토큰의 일치 여부와 `사내`의 IDF만 확인한다. 외부 라이브러리 없이 실행할 수 있다.

```python
from math import log

docs = [
    set("사내 VPN을 연결한다".split()),
    set("사내 계정 로그인 실패 시 잠긴다".split()),
    set("비밀번호를 변경한다".split()),
    set("장비를 지급한다".split()),
]

def matched_docs(term):
    return [i + 1 for i, doc in enumerate(docs) if term in doc]

for term in ("VPN", "VPN을", "로그인"):
    print(term, matched_docs(term))

n = len(docs)
df = len(matched_docs("사내"))
print("사내 IDF:", log((n - df + 0.5) / (df + 0.5)))
```

### 실행 결과

- 검색 예제에서 원래 질문은 모두 0점이지만, 상위 3개를 요청하면 동점 후보 중 일부가 돌아온다.
- 위 복습 코드의 예상 출력은 `VPN []`, `VPN을 [1]`, `로그인 [2]`, `사내 IDF: 0.0`이다. 목록의 숫자는 문서 번호다.

## 4. 실수 및 트러블슈팅

- 상황: VPN을 검색 점수에서 따로 제외하는 규칙이 있는 것처럼 보였다.
- 원인: 단어의 뜻이 아니라 토크나이저가 만든 조각을 비교한다. `VPN`은 정확히 일치하지 않은 경우이고, `사내`는 일치해도 IDF가 0인 경우다.
- 해결: 뜻으로만 판단하지 말고 질문과 문서를 `split()`으로 나눈 결과를 나란히 출력한다. 토큰이 같으면 문서 빈도와 가중치를 확인한다.
- 해결 결과: 이 예제에서는 `VPN을`보다 `로그인`이 계정 잠금 근거를 찾는 데 더 알맞다. 가장 점수가 높은 문서가 질문에 답하는 문서인지는 본문도 확인해야 한다.
