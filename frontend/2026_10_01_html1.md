## 1. 오늘 배운 내용과 목표

- 오늘 배운 주제: 브라우저 이벤트 처리 및 전파
- 오늘의 목표: 이벤트(사용자의 행동)에 맞춰 웹페이지가 동적으로 움직이도록 만드는 코드가 바로 프론트엔드의 핵심이다.
- 수업을 듣기 전 알고 있던 내용: 웹페이지가 동적으로 움직인다는 것은 알고 있었다.

## 2. 개념과 용어 정리

### 이벤트 처리기와 등록 방법 3가지
- 이벤트란 웹페이지 내에서 발생하는 모든 사용자 행동을 뜻함. 이를 알아채고 실행되는 함수를 이벤트 처리기(Event Handler) 또는 이벤트 리스너(Event Listener)라고 함.

#### HTML 속성과 DOM 프로퍼티 방식
- HTML 속성 설정: HTML 태그 내부에 `onclick` 같은 이벤트 속성을 직접 적고 자바스크립트 함수를 연결하는 기초적인 방식
- DOM 프로퍼티 설정: HTML과 자바스크립트를 분리하여, 스크립트 코드에서 요소를 가져와 객체의 속성에 함수를 대입한다.
- 특징: 두 방식 모두 하나의 요소에 하나의 이벤트 처리기만 등록할 수 있으며, 새로운 함수를 등록하면 이전 함수가 덮어씌워져 무효화됨!

```html
<!DOCTYPE html>
<html lang="ko">
<head>
    <meta charset="UTF-8">
    <title>이벤트 등록 방식</title>
</head>
<body>
    <!-- (1) HTML 속성에 이벤트 처리기를 설정합니다 -->
    <button onclick="alertAction()">알림 버튼</button>

    <!-- (2) DOM 객체 프로퍼티 방식으로 연결합니다 -->
    <button id="action-btn">결제 버튼</button>

    <script>
        // HTML 속성 방식에서 호출하는 함수입니다
        function alertAction() {
            alert("버튼을 클릭했습니다.");
        }

        // HTML 문서 구조(DOM 트리)가 완전히 준비되면 내부 코드를 실행합니다
        window.addEventListener("DOMContentLoaded", function() {
            // HTML 요소를 ID로 선택하여 변수에 저장합니다
            const actionButton = document.getElementById("action-btn");

            // DOM 객체의 onclick 프로퍼티에 함수를 대입합니다
            actionButton.onclick = function() {
                alert("처리가 완료되었습니다.");
            };
        });
    </script>
</body>
</html>
```

#### addEventListener 메서드 방식
- 하나의 HTML 요소에 복수의 이벤트 함수를 안전하게 누적 등록할 수 있는 표준 메서드
  - 구문 구조: `target.addEventListener(type, listener, useCapture);`
    - `target`: 이벤트를 등록할 DOM 노드
    - `type`: 이벤트 유형을 나타내는 문자열 (`"click"`, `"keyup"`, ...)
    - `listener`: 이벤트 발생 시 실행할 콜백 함수의 참조
    - `useCapture`: 이벤트 전파 단계 설정 (기본값 `false`는 버블링 단계를 의미)

#### 이벤트 리스너 제거 기법
- `removeEventListener` 메서드를 사용하면 등록된 이벤트 리스너를 삭제할 수 있음
  - 익명 함수로 등록한 이벤트 리스너는 삭제할 수 없으므로, 삭제가 필요한 경우 함수의 참조를 변수에 저장하거나 기명 함수로 정의해야 됨

### 브라우저 이벤트의 종류와 객체 활용
- 브라우저에서 일어나는 조작은 성격에 따라 분류되며, 이벤트가 발생하면 세부 정보를 담은 이벤트 객체(Event Object)가 생성됨

#### 마우스 이벤트의 종류 및 차이점
- 마우스 조작 관련 이벤트는 발생 시점과 마우스 포인터의 위치에 따라 세부적으로 구분됨

#### 마우스 이벤트 객체의 좌표 프로퍼티
- 마우스 이벤트가 발생하면 기준점의 위치에 따라 다양한 좌표 값이 제공됨

#### 키보드 이벤트의 종류 및 차이점
- 키보드 조작 관련 이벤트는 키가 눌리고 떼어지는 물리적 동작 순서에 따라 순차적으로 발생

#### 키보드 이벤트 객체의 프로퍼티
- 키보드 이벤트 발생 시 키의 세부 정보를 확인할 수 있는 프로퍼티

#### 기타 중요한 이벤트
- 웹페이지의 상태 변화나 입력 요소의 상태에 따라 발생하는 주요 이벤트
  - `DOMContentLoaded`: HTML 문서 구조의 분석이 완료되어 DOM 트리가 완성되었을 때 발생, 스크립트에서 요소를 안전하게 조작할 수 있는 시점

---

### 이벤트 전파 과정과 흐름 제어
- 이벤트가 HTML 요소에서 발생하면 계층 구조에 따라 상위 또는 하위 요소로 이벤트가 전달되는 과정을 **이벤트 전파(Event Propagation)**라고 함.

#### 이벤트 전파의 3단계
- 캡처링 단계: 이벤트가 Window 객체에서 출발하여 상위 요소부터 이벤트 타깃까지 하향 전파되는 단계
- 타깃 단계: 이벤트가 실제 발생한 요소에 도달하여 등록된 리스너가 실행되는 단계
- 버블링 단계: 이벤트가 타깃 요소에서 출발하여 상위 조상 요소들을 거슬러 올라가며 Window 객체까지 전파되는 단계 (`focus`, `blur` 등 일부 이벤트 제외)

#### 흐름 제어 메서드 실습
- `e.stopPropagation()`: 이벤트가 현재 요소 이후의 다른 요소로 전파되는 것을 차단.
- `e.preventDefault()`: 링크 이동이나 폼 제출 등 브라우저에 기본적으로 정의된 고유 동작을 취소함.

---

### 이벤트 리스너 안의 this와 데이터 전달
- 이벤트 리스너 내부의 `this` 키워드는 기본적으로 이벤트가 발생하여 처리를 담당하는 HTML 요소 객체를 가리킴

#### this 참조 문제의 해결 방법
- 객체의 메서드를 리스너로 연결하면 `this`가 객체 본연이 아닌 HTML 요소를 가리키는 현상이 일어남. 이를 해결하기 위해 `bind(객체)`를 활용하여 함수 내부의 `this`를 고정하거나, 익명 함수 혹은 화살표 함수 스코프로 묶어서 원래 대상을 유지시킴

#### 추가 데이터 전달 방법
- 이벤트 리스너에는 이벤트 객체 외에 임의의 매개변수를 직접 넘길 수 없으므로, 익명 함수를 중간 래퍼로 사용하여 인수를 전달함.

### 오늘의 단어 개념
| 용어/명령어 | 영문 / 키워드 | 뜻 및 주의점 |
|---|---|---|
| DOMContentLoaded | `DOMContentLoaded` | HTML 파싱이 완료되어 DOM 트리가 준비되었을 때 브라우저가 발생시키는 이벤트 |
| 이벤트 리스너 | Event Listener | 특정 이벤트 신호가 감지되었을 때 예약된 처리를 수행하는 콜백 함수 |
| 버블링 | Bubbling | 타깃 요소에서 발생한 이벤트가 상위 조상 요소들로 거꾸로 거슬러 올라가며 전파되는 과정 |
| 캡처링 | Capturing | Window 객체에서 시작하여 이벤트가 발생한 타깃 요소까지 하향하며 조상 요소를 탐색하는 과정 |
| 이벤트 객체 | Event Object | 사용자 조작 시 발생한 이벤트의 좌표, 입력 문자 정보, 제어 메서드를 포괄하는 브라우저 생성 객체 |
| stopPropagation | `stopPropagation()` | 현재 요소에서 처리를 끝내고 이벤트가 상위 또는 하위 요소로 더 이상 전파되지 않도록 차단하는 메서드 |
| preventDefault | `preventDefault()` | 링크 이동이나 폼 제출 등 웹 브라우저 환경에 내장된 고유의 기본 동작을 가로채 취소하는 메서드 |
| focus / blur | `focus` / `blur` | 요소가 포커스를 얻거나 잃었을 때 발생하며, 계층 간 버블링 전파가 일어나지 않는 고유 이벤트 |

## 3. 오늘의 핵심
- ⭐️ 반드시 기억할 내용: 이벤트 리스너는 특정 이벤트가 발생했을 때 실행할 함수를 미리 등록하는 것이다. addEventListener로 동작을 연결하고, removeEventListener로 연결을 해제할 수 있다. 이벤트는 캡처링 → 타깃 → 버블링 순서로 전달되며, 버블링하지 않는 이벤트도 있다.

- 💡 참고로 알아둘 내용: 마우스·키보드 이벤트의 종류와 좌표 프로퍼티는 전부 외우기보다 필요한 기능을 만들 때 찾아 활용하면 된다. 좌표는 화면·문서·요소 등 어디를 기준으로 측정하는지 구분하는 것이 중요하다.

- ⚠️ 헷갈리기 쉬운 주의점: 함수 등록과 실행은 다르다. addEventListener의 true·false는 반복 실행 여부가 아니라 캡처링 사용 여부를 정한다. stopPropagation()은 이벤트 전파를 막고, preventDefault()는 링크 이동 같은 기본 동작을 취소한다. 리스너를 제거해도 HTML 요소 자체가 사라지지는 않는다.

- 한 문장 요약: 이벤트 처리는 웹페이지에서 발생한 일에 동작을 연결하고, 그 동작의 전달 흐름과 기본 행동을 제어하는 방법이다.

## 4. 느낀 점과 다음 학습
- 잘 이해한 부분: HTML 요소에 id를 지정하고, getElementById로 찾아 변수에 담은 뒤 클릭 동작을 연결하는 흐름을 이해했다. 같은 요소에 클릭 리스너를 여러 개 등록하면 한 번의 클릭으로 여러 동작이 실행된다는 점도 알게 되었다.

- 아직 어려운 부분: 캡처링과 버블링의 실행 순서, true·false의 의미가 아직 헷갈린다. 코드를 읽고 흐름을 설명하는 것보다 직접 조건문을 작성해 원하는 동작을 만드는 것이 더 어렵게 느껴졌다.

- 다음에 복습할 내용: 클릭할 때마다 상자 색이 바뀌는 조건문을 다시 작성해보고, 부모·자식 요소의 콘솔 출력으로 이벤트 전파 순서를 확인해볼 것이다. stopPropagation()과 preventDefault()를 각각 사용했을 때와 사용하지 않았을 때의 차이도 비교해볼 것이다.

- 오늘의 느낀 점: 처음에는 버튼을 누르면 함수가 실행되는 정도로 생각했는데, 이벤트가 전달되는 순서와 기본 동작까지 제어할 수 있다는 것을 배웠다. 내용이 복잡해도 코드를 위에서부터 하나씩 풀어보니 이해가 쉬워졌다. 상자 색을 다시 돌아오게 바꾸는 것처럼 작은 동작을 직접 수정해보는 과정이 재미있었다.
