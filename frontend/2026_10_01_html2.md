## 2. 개념과 용어 정리

### 비동기 프로그래밍의 이해와 스레드
- 비동기식 처리: 특정 작업의 완료를 기다리지 않고 다음 코드를 즉시 실행하는 방식
- 자바스크립트는 하나의 처리 흐름을 가진 싱글 스레드(Single Thread) 언어이며, 네트워크 요청처럼 실행 시간이 긴 작업을 효율적으로 처리하기 위해 비동기 프로그래밍 구조를 활용함.

#### 스레드(Thread)의 개념
- 운영체제에서 코드를 실행하는 하나의 흐름 또는 작업 단위
- 싱글 스레드와 멀티 스레드: 하나의 스레드는 한 번에 하나의 명령만 처리할 수 있음. 반면 멀티 스레드는 여러 작업을 동시에 분할 처리할 수 있는 구조

#### 자바스크립트가 싱글 스레드를 선택한 이유
- 브라우저 환경에서 여러 스레드가 동시에 화면(DOM)을 수정하면 충돌과 동기화 문제가 발생할 수 있음.
- 이를 방지하기 위해 자바스크립트는 단일 흐름을 유지하되, 시간이 오래 걸리는 작업은 비동기 방식으로 브라우저(Web API 등) 외부 창구에 위임함.

#### 비동기 처리의 특징: 실행 순서와 종료 순서
- 비동기 함수는 호출된 순서대로 실행되지만, 작업의 종료 시점은 작업마다 소요되는 시간에 따라 달라짐.

---

### 콜백 함수와 콜백 지옥
- 콜백 함수(Callback Function): 비동기 작업의 실행 순서를 보장하기 위해 다른 함수의 인자로 전달되는 함수
- 비동기 작업은 종료 시점이 일정하지 않기 때문에, 특정 작업이 완료된 후 다음 작업을 순차적으로 실행해야 할 때는 함수의 실행 권한을 넘겨주는 방식을 사용해야 됨.

#### 콜백 함수를 통한 순서 보장
- 비동기 함수 내부에서 작업이 끝나는 시점에 인자로 받은 콜백 함수를 호출하여 순차적인 흐름을 구현함.

#### 콜백 지옥(Callback Hell)
- 순차적 처리가 필요한 비동기 작업이 늘어남에 따라 콜백 함수의 중첩 단계가 깊어지는 현상
- 문제점: 코드의 구조가 복잡해져 가독성이 크게 떨어지고, 에러 발생 시 디버깅과 유지보수가 어려워짐.

---

### Promise 객체
- 비동기 작업의 완료 또는 실패 상태를 추적하고, 콜백 함수의 다중 중첩 문제를 해결하는 객체
- 자바스크립트 ES6에서 도입되었으며, 비동기 작업의 흐름을 연속적인 마침표(`.`) 메서드로 연결(Chaining)하여 가독성을 높여줌.

#### Promise의 3가지 상태
1. Pending(대기): 비동기 처리가 아직 완료되지 않은 초기 상태
2. Fulfilled(이행): 비동기 작업이 성공적으로 완료된 상태 (`.then()`으로 처리)
3. Rejected(거부): 비동기 작업이 실패하여 오류가 발생한 상태 (`.catch()`로 처리)

#### Promise 기반의 함수 정의 및 순차 실행 (.then / .catch)
- 구조적 변화: 함수가 콜백을 인자로 받지 않고, 비동기 작업의 약속 정보가 담긴 Promise 객체를 즉시 반환(return)함.
- Chaining(체이닝): 앞선 작업이 성공하면 `.then()` 내부에서 다음 비동기 함수를 호출 및 반환하여 콜백 지옥을 수평적인 구조로 펼쳐줌.

#### Promise.resolve()와 Promise.reject()
- `Promise.resolve(value)`: 전달받은 value 값을 가진 이행 상태의 Promise 객체를 즉시 반환
- `Promise.reject(error)`: 전달받은 error 값을 가진 거절 상태의 Promise 객체를 즉시 반환

#### Promise.all()과 Promise.race()
- 다수의 비동기 작업을 병렬로 다룰 때 사용하는 메서드
- `Promise.all(배열)`: 전달된 모든 Promise가 전부 이행될 때까지 기다린 후 결과값을 배열로 반환하며, 하나라도 실패하면 즉시 거절(Rejected) 처리됨.
- `Promise.race(배열)`: 전달된 Promise 중 가장 먼저 완료되는 작업의 결과(성공 또는 에러)만을 반환함.

### async / await 문법과 비동기 제어 흐름
- Promise를 기반으로 동작하지만, 비동기 코드를 마치 동기식 코드처럼 읽기 쉽고 직관적으로 작성할 수 있게 해주는 ES8(ES2017) 문법

#### 핵심 규칙 및 구조적 개선점
- 내부적인 Promise 활용: 문법이 개선되더라도 `async` 함수가 제어하는 대상과 반환하는 결과물은 여전히 Promise 객체임. 즉, 가독성이 향상된 문법적 설탕(Syntactic Sugar)임.
- await의 실행 조건: `await` 키워드는 반드시 `async` 키워드가 붙은 함수 내부에서만 실행될 수 있음. (일반 함수나 비동기 함수 밖에서 사용 시 문법 에러 발생)
- 예외 처리의 통합: Promise의 `.catch()` 대신 자바스크립트 표준 예외 처리 구문인 `try...catch` 블록을 사용하여 동기/비동기 에러를 한 곳에서 일관되게 관리할 수 있음.

---

### Fetch API를 활용한 네트워크 통신
- 브라우저 환경에서 원격 서버로 HTTP 요청을 전송하고 응답을 수신하는 표준 Web API
- `fetch()`는 비동기 함수로, 호출 시 Promise 객체를 반환함.

#### 데이터 조회를 위한 GET 요청
- 서버에 저장된 특정 자원을 조회하여 자바스크립트 객체 형식으로 파싱(JSON 파싱 등)하는 과정
- `fetch(url)` 후 `.then(response => response.json())` 또는 `await response.json()` 형태로 처리

#### 데이터 전송을 위한 POST 요청
- 서버에 새로운 데이터를 등록하기 위해 HTTP 요청 방식(`method: "POST"`), 헤더(`headers`), 전송 본문(`body: JSON.stringify(...)`) 등의 옵션을 설정하여 전송하는 단계

---

### [참고] 타이머 Web API: setTimeout과 setInterval
- 브라우저는 특정 시간이 지난 후에 코드를 1회 실행하거나, 일정 시간마다 코드를 반복 실행하는 타이머 기능을 제공함.
- `setTimeout(callback, ms)`: 일정 시간 경과 후 콜백 실행 (취소 시 `clearTimeout(timerId)`)
- `setInterval(callback, ms)`: 일정 시간 주기마다 콜백 반복 실행 (취소 시 `clearInterval(timerId)`)

### ⭐️ 필수 (실무 핵심 90%) - 반드시 기억
| 용어/명령어 | 영문 / 키워드 | 뜻 및 주의점 |
|---|---|---|
| 싱글 스레드 | Single Thread | 코드를 실행하는 주체가 1개인 구조. 자원 충돌이 없으나 긴 연산 시 블로킹 방지를 위해 비동기 처리가 필수적임 |
| 멀티 스레드 | Multi Thread | 코드를 실행하는 주체가 여러 개인 구조. 동시 처리가 가능하나 동기화 문제와 데이터 충돌 위험이 있음 |
| 콜백 지옥 | Callback Hell | 비동기 순서를 맞추기 위해 콜백 함수를 연속 중첩하여 코드 가독성과 유지보수성이 급격히 저하되는 현상 |
| 프로미스 | Promise | 비동기 작업의 상태(대기/이행/거부)를 표현하고 `.then()` 체이닝을 통해 콜백 지옥을 해소하는 객체 |
| async / await | `async` / `await` | Promise 기반 코드를 동기식 코드 형태처럼 깔끔하게 작성할 수 있게 돕는 최신 문법 |
| try...catch | `try { ... } catch` | `async/await` 환경에서 비동기 작업 중 발생한 에러를 안전하게 가로채 처리하는 표준 예외 처리 구문 |
| Fetch API | `fetch()` | 원격 서버와 HTTP 통신을 수행하는 최신 Web API로, 호출 시 Promise를 반환함 |

## 3. 오늘의 핵심
- ⭐️ 반드시 기억할 내용: 
  - 자바스크립트는 싱글 스레드 언어이므로, 화면 멈춤(블로킹)을 방지하기 위해 시간이 걸리는 작업(네트워크 통신, 타이머 등)은 비동기로 처리한다.
  - 비동기 처리의 발전 흐름: `콜백 함수` $\rightarrow$ `Promise 객체 (.then / .catch)` $\rightarrow$ `async / await + try...catch`
  - `await`는 비동기 작업의 완료를 동기식 코드처럼 기다려주며, 반드시 `async` 함수 내부에서만 사용해야 한다.
  - `fetch()`는 서버와의 HTTP 통신을 위한 표준 API로 기본적으로 Promise를 반환하며, 응답 본문을 읽기 위해 `response.json()` 역시 비동기로 처리해야 한다.

- 💡 참고로 알아둘 내용: 
  - `setTimeout`과 `setInterval`은 브라우저 Web API이며, 함수 호출 시 반환되는 고유 타이머 ID를 이용해 `clearTimeout`, `clearInterval`로 동작을 취소할 수 있다.
  - 다수의 비동기 처리가 필요할 때 `Promise.all`은 모든 작업이 끝날 때까지 병렬로 기다려주고, `Promise.race`는 가장 빠른 작업 결과만 취한다.

- ⚠️ 헷갈리기 쉬운 주의점: 
  - 비동기 코드는 작성된 순서대로 즉시 끝나는 것이 아니라 백그라운드 작업 완료 후 실행되므로 코드 실행 순서와 종료 순서를 혼동하지 말아야 한다.
  - `await`는 아무 곳에서나 쓸 수 없으며 반드시 `async` 함수 안에서만 유효하다.
  - `async/await` 환경에서는 Promise의 `.catch()` 대신 표준 `try...catch` 문을 사용하여 에러를 잡아야 한다.

- 한 문장 요약: 
  - 비동기 프로그래밍은 싱글 스레드 자바스크립트에서 멈춤 없이 효율적으로 작업을 처리하기 위한 핵심 기술이며, `async/await`와 `fetch API`를 활용해 가독성 높고 안전하게 제어할 수 있다.

## 4. 느낀 점과 다음 학습
- 잘 이해한 부분: 
  - 자바스크립트가 싱글 스레드인데도 화면이 멈추지 않는 이유(비동기 위임 구조)를 명확히 이해했다.
  - 콜백 지옥이 왜 발생하고, 이를 Promise와 `async/await` 문법이 어떤 구조로 깔끔하게 해결해 주는지 그 발전 배경을 정리할 수 있었다.
  - `async` 함수 안에서 `await`와 `try...catch`를 조합해 사용하는 패턴의 직관성과 편리함을 배웠다.

- 아직 어려운 부분: 
  - 여러 비동기 호출이 서로 의존성을 가질 때의 복잡한 실행 흐름과, `fetch()` 통신 시 헤더 및 상태 코드(4xx, 5xx)에 따른 예외 처리 세부 분기를 작성하는 것은 아직 연습이 더 필요하다.
  - `Promise.all` 등 병렬 처리 시 에러 핸들링 기법이 완전히 익숙하지는 않다.

- 다음에 복습할 내용: 
  - `fetch API`를 이용해 실제 Mock 서버나 오픈 API로 GET, POST 요청을 직접 보내고, 받아온 JSON 데이터를 화면(DOM)에 동적으로 그려보는 실습 코드를 작성해볼 것이다.
  - `async/await` 함수에 `try...catch`를 적용하여 네트워크 단절이나 에러 상황을 우아하게 처리하는 패턴을 다시 복습할 예정이다.

- 오늘의 느낀 점: 
  - 처음 비동기라는 말을 접했을 때는 막연하고 어려워 보였는데, 스레드 개념부터 시작해서 콜백, Promise, async/await로 이어지는 발전 과정을 순서대로 짚어보니 각 문법이 왜 생겨났는지 자연스럽게 이해할 수 있었다.
  - 특히 복잡한 비동기 작업도 `async/await`를 쓰면 동기 코드처럼 편하게 작성할 수 있다는 점이 인상 깊었다. 웹 개발에서 백엔드와의 통신은 필수적인 만큼, 오늘 배운 Fetch와 비동기 제어를 확실하게 손에 익혀두어야겠다.
