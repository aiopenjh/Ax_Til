## 2. 개념과 용어 정리

### 타입스크립트의 등장 배경
타입스크립트는 마이크로소프트가 개발한 오픈소스 프로그래밍 언어, 자바스크립트에 정적타입 기능을 더한언어이다. 자바스크립트를 확장하는 형태로 설계되었으며, 모던 프론트 엔드 개발의 표준으로 자리잡고 있는 대표적인 Altjs이다.

#### 1-1 대규모 개발에서 자바스크립트의 문제점
- 에러 검출의 지연 : 코드를 실행하기 전에는 에러를 잡을 수 없어, 실제 서비스 작동 중에 버그가 발생하기 쉬움
- 협업의 어려움 : 여러명의 개발자가 함께 코드를 작성할 때, 함수에 어떤 데이터를 넘겨야 하는지 명확한 규격이 없어 오해가 발생

#### 1-2 타입스크립트가 대세가 된 이유
- 높은 개발 생산성 : 컴파일 시점에 에러를 빠르게 발견하여 코드의 안정성을 향상시킴
- 완벽한 상위 호환성 : 자바스크립트의 문법을 그대로 포함하고 확장한 형태
- 낮은 도입 비용 : 기존 자바스크립트로 작성된 애플리케이션 코드를 그대로 가져와도 작동하므로 부드러운 전환이 가능

### 자바스크립트와 타입스크립트 비교
타입스크립트 코드는 빌드 도구를 통해 최종적으로 자바스크립트로 변환되어 실행됨, 웹 브라우저는 자바스크립트만 읽을 수 있기 때문에, 타입스크립트라는 독립된 소스코드를 자바스크립트로 바꾸어 주는 특별한 변환 단계(트랜스 파일러, Transpiler)가 필요

#### 2-1
- 트랜스파일(Transpile) : 하나의 프로그래밍 언어로 작성된 소스코드를 비슷한 수준의 다른 프로그래밍언어로 변환(Source-to-Source)하는 작업, 이 역할을 수행하는 도구를 트랜스 파일러라고 부름
- 컴파일(Compile)과의 차이 : 컴파일이 사람이 읽는 텍스트 코드를 컴퓨터 시스템이 직접 처리하는 0과1 기반의 '기계어'로 바꾸는 광범위한 작업이라면, 타입스크립트는 기계어가 아닌 '자바스크립트 코드'로 변환되므로 명확히는 트랜스 파일에 해당
- 성능의 영향없음 : 최종 결과물을 순수한 자바스크립트 형태로 치환되어 브라우저에서 실행되므로, 언어 추가로 인한 작동 속도 저하나 구동 성능 변화가 전혀 발생하지않음

#### 2-2 코드 구조 비교(상위 호환성 확인)
- 파일 확장자의 변화 : 자바스크립트 코드를 작성할때는 script.js 처럼 .js확장자를 사용했지만, 타입 스크립트 코드를 작성할 떄는 .ts 라는 확장자로 사용됨

#### 2-3 타입 스크립트의 주요 확장 기능과 특징
- 타입정의 및 안정성 : 데이터 종류를 고정하고 빈값(Null, undefined)으로 인해 프로그램이 멈추는 현상을 방지
- 고도화된 설계지원: 구조적 규격을 정의하는 인터페이스(interface)와 복잡한 데이터 모델을 위한 제네릭(Generic)등을 지원함
- 온라인 테스트 환경 : 복잡한 설치없이 웹브라우저에서 타입스크립트 코드를 즉시 시험해 볼 수있는 공식 온라인도구가 제공
- 프레임 워크 자동 변환: 실제 웹 애플리케이션 개발단계(Next.js)에서는 빌드 도구가 변환 과정을 자동으로 처리해줌

### TypeScript의 5가지 기본 원시타입
#### 원시타입(Primitive Type)
더이상 세부적으로 분해할 수 없는 데이터의 최소 단위를 의미, 하나의 변수에 하나의 값만 할당됨
- string, number, boolean // 타입 문자 숫자 논리값
- null과 undefined 타입 : 
  - null - 값이 없음을 명시적으로 나타내기 위해 의도적 할당
  - undefined - 변수 선언한 후 값이 할당 되지 않았을때 시스템이 부여하는 기본상태

### 배열(Array)타입 정의하기
데이터 타입이 동일한 복수의 요소를 순차적으로 나열하여 관리하는 선형 자료구조
- 대괄호 표기법(Type[]) : 변수 타입 식별자 뒤에 []를 붙여 해당 타입의 요소들로 구성된 배열임을 명시
- 제네릭 표기법(Array<Type>) : 전역 객체인 Array에 제네릭 문법을 사용하여 내부 요소의 타입을 정의

### 고정 길이 데이터, 튜플(Tuple)
- 튜플의 선언 구조
  - 순서와 길이의 제약 : 각인덱스마다 정해진 타입이 일치해야 하며, 지정된 길이를 벗어나는 데이터 할당을 방지
  - 리액트 상태 구조화의 모태 : 컴포넌트의 상태 값과 해당 상태를 변경하는 함수를 정해진 순서로 반환하는 구조의 기반

### 특수 타입(any, unknown, never)
특정한 상황이나 형식이 명확하지 않은 데이터를 처리하기 위해 정의된 타입 규격, 데이터 형식을 사전에 확정하기 어렵거나 예외적인 상황을 처리할 때 코드의 안정성을 확보하기 위해 사용

- 타입 검사를 제외하는 any타입 : 타입스크립트의 컴파일 시점 정적 타입 검사를 수행하지 않도록 설정하는 타입 / 모든 종류의 데이터를 대입할 수 있으나, 컴파일러가 타입 오류를 감지하지 않으므로 실행 시점에 오류가 발생할 수 있음.

```ts
// any 타입의 할당 및 컴파일러 검사 제외 확인
let flexibleValue: any = "정산 완료"; // 초기값으로 문자열을 대입합니다.

flexibleValue = 10000;              // 숫자를 대입해도 컴파일 에러가 발생하지 않습니다.
flexibleValue = true;               // 불리언 값을 대입해도 정상적으로 허용됩니다.

// 존재하지 않는 메서드를 호출해도 컴파일 시점에는 에러를 감지하지 못합니다.
flexibleValue.calculateTotalScores();
```

- 타입 검증과 타입 좁히기를 강제하는 unknown 타입 : any와 동일하게 모든 종류의 데이터를 대입할 수 있지만, 정체를 확인하기 전에는 사용을 제한하는 안전한 타입
  - 특징 : 외부 API의 응답 데이터처럼 형식을 미리 알 수 없는 데이터를 다룰 때 컴파일 시점의 안정성을 보장하기 위해 사용
  - 타입 좁히기(Type Narrowing): 조건문을 통해 컴파일러에게 특정 변수의 타입을 명확히 입증하여 해당 블록 안에서 안전하게 데이터에 접근 할 수있도록 허용하는 과정

```ts
// unknown 타입의 제약 및 타입 좁히기 구현
let rawResponse: unknown;

// typeof 연산자를 활용한 원시 타입 좁히기
rawResponse = "  TypeScript  ";
if (typeof rawResponse === "string") {
    // 이 조건문 내부에서 rawResponse는 string 타입으로 확정되어 문자열 메서드를 쓸 수 있습니다.
    console.log("문자열 처리:", rawResponse.trim());
}

// Array.isArray()를 활용한 배열 타입 좁히기
rawResponse = [10, 20, 30];
if (Array.isArray(rawResponse)) {
    // 이 조건문 내부에서 rawResponse는 배열 타입으로 확정되어 고차 함수를 안전하게 실행할 수 있습니다.
    const doubled = rawResponse.map((num: number) => num * 2);
    console.log("배열 처리 결과:", doubled);
}
```

- any 보다 unknown 사용을 지향해야 하는이유 : 타입스크립트에서는 타입 안정성을 보장하기 위해 any대신 unknown을 사용하는것을 권장, 두 타입은 값을 수용하는 범위는 같지만, 사용 할 때의 제약 조건에서 큰차이가있음
  - typeof 연산자 : 원시타입 / string, number, boolean 등 기본 데이터 타입을 판별
  - Array.isArray() : 배열구조 / 데이터가 배열 형식인지 검증할 때 사용
  - 사용자 정의타입가드 : 객체 및 커스텀 타입 / is 키워드를 사용하여 객체의 내부 속성 구조를 직접 검증

- 값을 반환하지않는 never 타입 : 특징 / 의도적으로 예외 오류를 발생시키거나 무한 루프를 실행하여 반환값 자체가 존재하지 않는 구조에 지정됨
- 타입스크립트 타입 계층구조
  - 최상위타입(Top type) : unknown은 시스템의 모든 데이터 타입을 포함할 수있는 상위 계층 타입
  - 최하위타입(Bottom type) : never는 어떤 값도 포함하지 않는 하위 계층의 타입

### 타입추론 (Type inference)
코드를 작성할 때 타입을 직접 명시하지 않아도 대입된 초기값을 기준으로 타입을 자동 지정하는 메커니즘, 명시적 선언 코드를 줄이면서 정적 타입 시스템의 안정성을 유지할 수 있도록 지원

- 초기값에 의한 타입 확정 규칙 : 변수를 선언하는 동시에 값을 대입하면 컴파일러가 해당 데이터의 형식을 분석하여 변수의 타입을 고정 / 특징 : 변수의 타입이 결정된 이후에는 다른 타입의 데이터를 대입할 수 없음

```ts
// 초기값을 기반으로 정해지는 타입 유추 규칙
let regularPrice = 45000;       // 숫자가 대입되었으므로 number 타입으로 추론됩니다.
let accountId = "user_7789";    // 문자열이 대입되었으므로 string 타입으로 추론됩니다.

// 정해진 타입과 다른 형식의 데이터를 대입하려고 하면 컴파일 에러가 발생합니다.
// regularPrice = "품절상태";
```

- 타입 추론 실습 및 검증

```ts
// tslab 환경에서 실행 가능한 타입 추론 검증 코드
let accumulatedScore = 250;           // 초기값을 기준으로 number 타입으로 지정됩니다.
let isLevelCleared = false;           // 초기값을 기준으로 boolean 타입으로 지정됩니다.

// 동일한 타입의 데이터 대입 시도
accumulatedScore = 320;               // 동일한 수치형 데이터이므로 할당이 가능합니다.
isLevelCleared = true;                // 동일한 논리형 데이터이므로 할당이 가능합니다.

console.log("최종 점수:", accumulatedScore);
console.log("클리어 여부:", isLevelCleared);

// 아래 코드의 주석(//)을 해제하고 실행하면 타입 불일치로 인해 컴파일 에러가 발생합니다.
// accumulatedScore = "게임종료";       // 에러: 'string' 형식을 'number' 형식에 할당할 수 없습니다.
```

### 타입 단언(Type Assertion)
컴파일러가 유추하는 타입보다 개발자가 해당 데이터의 타입을 더 명확히 알고 있을때, 컴파일러에게 해당 타입으로 간주하도록 직접 지시하는 구문 / 형변환과 달리 실제 실행시점의 데이터를 변환하지 않으며 컴파일 시점의 타입검사만 재정의

- as 키워드와 타입 단언 : 변수나 표현식 뒤에 as 타입명을 붙여 컴파일러에게 데이터의 타입을 지정할 수있음

```ts
// as 키워드를 활용한 타입 단언
let unknownData: unknown = "TypeScript 5.0";

// 컴파일러는 unknownData의 속성을 모르지만, 개발자가 string임을 확신하여 단언
let strLength: number = (unknownData as string).length;

console.log("문자열 길이:", strLength);
```

- 타입 단언 활용 (JSON 및 API데이터) : Node.js 환경에서 외부파일 을 읽거나 API 응답 데이터를 파싱할때, 컴파일러는 변환된 데이터의 내부 속성을 알지 못함, 이때 미리 정의해둔 인터페이스나 타입 구조로 단언하여 안전하게 속성에 접근할수있음

```ts
interface UserProfile {
    id: number;
    name: string;
    role: string;
}

// 외부에서 전달받은 JSON 문자열 데이터
const rawJsonData = '{"id": 101, "name": "김스파르타", "role": "admin"}';

// JSON.parse() 결과를 UserProfile 타입으로 단언
const user = JSON.parse(rawJsonData) as UserProfile;

// 타입 단언을 통해 자동 완성 및 속성 접근 지원
console.log("사용자 ID:", user.id);
console.log("사용자 이름:", user.name);
console.log("권한:", user.role);
```

- 타입 단언 사용 시 주의사항 : 타입 단언은 컴파일러의 타입 검사기를 강제로 우회하는 기능, 자바스크립트 변환 시 삭제됨. 실제 데이터가 숫자인데 as string 으로 단언하더라도 실행 시점에 숫자가 문자열로 바뀌지 않음. 따라서 외부 데이터의 형식을 100% 확신할 수 있는 상황에서만 제한적으로 사용

```ts
// 잘못된 타입 단언 예시 (컴파일은 통과하지만 런타임 오류 발생)
let rawNumber: unknown = 12345;

// 실제 값은 숫자이지만 개발자가 string으로 잘못 단언 (컴파일 타임에 감지 못 함)
let wrongAssertedStr = rawNumber as string;

// 실행 시점에 toUpperCase() 함수가 없어 런타임 에러 발생!
console.log(wrongAssertedStr.toUpperCase()); // TypeError: wrongAssertedStr.toUpperCase is not a function
```

### ⭐️ 필수 (실무 핵심 90%) - 반드시 기억
| 용어/문법 | 뜻 | 기억할 점 / 주의점 |
|---|---|---|
| `unknown` | 안전한 최상위(Top) 타입 | `any` 대신 사용을 지향하며, 사용 전 반드시 타입 좁히기(검증) 필수 |
| 타입 좁히기 | `typeof`, `Array.isArray()` 등으로 타입을 좁힘 | 런타임 검사로 컴파일러에게 타입을 입증하여 안전하게 메서드 접근 |
| `[T1, T2]` (튜플) | 길이와 각 요소의 타입 순서가 고정된 배열 | 리액트의 `useState` 훅 반환값(`[state, setState]`)의 모태가 되는 구조 |
| `Type[]` | 특정 타입 요소들로 이루어진 배열 정의 | 동일한 타입의 데이터만 순차적으로 담는 가장 표준적인 배열 표기법 |
| 타입 추론 | 초기값을 기준으로 변수 타입을 컴파일러가 자동 지정 | 불필요한 타입 코드를 줄여주며, 타입 확정 후 다른 타입 대입 불가 |
| `as` (타입 단언) | 컴파일러에게 특정 타입으로 간주하도록 직접 지시 | 런타임 데이터 변환이 아니므로 외부 데이터 형식을 100% 확신할 때만 사용 |
| `any` | 컴파일러의 정적 타입 검사를 완전히 비활성화 | 런타임 에러를 유발할 위험이 매우 커 실무에서는 사용을 강력히 지양 |

### 💡 참고 (검색용) - 이해만 하고 넘어가기
| 패턴/문법 | 뜻 | 필요할 때 찾는 팁 |
|---|---|---|
| `Transpile` | 소스코드를 다른 언어 소스코드로 변환 | TS가 브라우저 실행을 위해 순수 JS로 치환되는 과정 (성능 영향 없음) |
| `AltJS` | 자바스크립트를 대체/확장하기 위한 언어군 | TypeScript, CoffeeScript 등이 대표적이며 TS가 모던 표준 |
| `never` | 어떤 값도 가질 수 없는 최하위(Bottom) 타입 | 에러를 던지거나(`throw`) 무한 루프로 반환값이 없는 함수에 지정 |
| `Array<Type>` | 제네릭을 활용한 배열 표기법 | `Type[]`와 동일하며 제네릭 인터페이스 다룰 때 주로 검색 |
| `null` vs `undefined` | 값의 의도적 부재 vs 할당되지 않은 초기 상태 | 원시 타입 중 빈 값 처리 시 유니온 타입(`string \| null`)에 자주 활용 |

## 3. 오늘의 핵심
- ⭐️ 반드시 기억할 내용: 타입스크립트는 자바스크립트에 정적 타입 검사를 더해 실행 전에 타입 관련 실수를 발견하도록 돕는다. 타입을 직접 지정하지 않아도 초기값을 통해 추론할 수 있다.
- 💡 참고로 알아둘 내용: 배열은 요소의 타입을 정하고, 튜플은 위치별 타입과 길이 규칙을 표현한다. any는 해당 값의 타입 검사를 느슨하게 만들고, unknown은 타입을 확인한 뒤 필요한 기능을 사용하도록 제한한다.
- ⚠️ 헷갈리기 쉬운 주의점: 타입 단언인 as는 실제 값을 바꾸거나 데이터를 검증하지 않는다. Array.isArray() 역시 배열 내부 요소의 타입까지 확인해주지는 않는다.
한 문장 요약: 타입스크립트는 실행 전 타입 실수를 줄여주지만, 외부에서 들어온 데이터는 실행 중에도 직접 확인해야 한다.

## 4. 느낀 점과 다음 학습
- 잘 이해한 부분: 변수에 타입을 지정하는 이유와 초기값에 따라 타입이 자동으로 추론되는 흐름을 정리했다.
- 아직 어려운 부분: any·unknown·never의 차이와 타입 좁히기·타입 단언을 각각 언제 사용해야 하는지 더 익힐 필요가 있다.
- 다음에 복습할 내용: 같은 변수에 다른 타입을 넣어 오류를 확인하고, unknown 값을 typeof 조건문으로 좁혀 사용하는 예제를 다시 연습한다.
- 오늘의 느낀 점: 자바스크립트에서 값만 넣어 쓰던 변수에도 데이터 종류를 명확하게 정할 수 있다는 점을 배웠다. 문법을 외우는 데 그치지 않고, 기존 투두리스트의 제목과 완료 여부에 타입을 붙이며 익혀보고 싶다.
